# 做了什麼、沒做什麼

專案已進入維護期，不再有進行中的任務。設計過程的細節在 [archive/](archive/)，其餘看 git 歷史。

## 做了什麼

| 項目 | 一句話 |
|---|---|
| 離站決策首頁 | 本站每條路線的狀態（可搭／等／未發車／末班已過），大字顯示 |
| 台語語音 | ASR 聽短指令、TTS 逐句播報；說話途中可打斷（WebRTC） |
| 串流回覆 | 回答逐句產生、逐句出聲，不等整段講完才開口 |
| 聽錯救援 | 站名或路線聽錯時，工具回相近候選，模型用確認句再問（見下） |
| 路線規劃 | 地圖點目的地，OTP 算路線，畫在地圖上 |
| 後台 `/admin` | 不重啟就能切換站牌與方向 |
| 方向過濾 | 自動隱藏「終點站到站」的方向；循環路線不過濾 |
| 公車資料 | 只用 TDX；共用限速器、3 秒等待上限、靜態站序索引（見 [TDX](tdx-tiers.md)） |
| 正式部署 | systemd + Nginx，失敗自動回切，可指定版本 rollback（見 [部署](deployment/production.md)） |
| 觀測 | OpenTelemetry → SigNoz（見 [觀測](observability.md)） |

### 聽錯救援的成果

60 題測試集（六類、含對照組），完全答對從 41.7% 提高到約 90%；幻覺否認、退化迴圈、誤救都降到 0。

做法是：**真實狀態由工具給，4B 小模型只負責改寫成確認句。** 只靠 prompt 試過兩次，都沒用。

還沒解決：模型在呼叫工具前自己改字、或改寫時複誦錯字（各約 1–2/60）。要再往上需要換大模型，或在 ASR 端加 hotword biasing（沒做）。

### 延遲的真正原因

語音回應曾經慢到 119 秒。根因是 TDX 免費方案的限流，不是程式慢。處理後虎尾查詢降到 0.07 秒，429 錯誤歸零。

## 沒做

- 數位站務員的 3D 視覺狀態機：等組員提供模型 API
- 到站時間改存絕對時刻：被限流用到舊快取時，「幾分鐘後到」會念錯
- 路線站序快取改成一天一次：每月可省約 20 點 TDX
- 前端沒有測試（vitest 沒裝）；PiP 語音 UX 沒做實機驗證
- Demo 腳本、報告素材、使用者試用

### 想擴充的方向

- 附近景點與餐廳查詢、校園知識
- 附近站牌（需要 GPS）
- 有限目的地候選確認（站名、醫院、車站、學校）、最多一次轉乘的建議
- 對話紀錄改存 Redis（目前綁單機 SQLite）
- 觀測內容的保留期限與遮罩規則
