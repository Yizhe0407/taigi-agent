# 做了什麼、沒做什麼

專案已經結束開發，只做維護。設計過程的細節在 [archive/](archive/)，其餘看 git 歷史。

## 做了什麼

| 項目 | 一句話 |
|---|---|
| 離站決策首頁 | 本站每條路線的狀態大字顯示（狀態與門檻見 [產品定位](product-positioning.md#它給的答案)） |
| 數位站務員小芸 | Live2D 角色，依對話狀態換表情（待機、聆聽、思考、說話、出錯），嘴型跟著聲音動 |
| 台語語音 | ASR 聽短指令、TTS 逐句播報；說話途中可以打斷（WebRTC） |
| 串流回覆 | 回答逐句產生、逐句出聲，不等整段講完才開口 |
| 聽錯救援 | 聽錯路線或站名時，工具自己改查最接近的候選，附確認句回答（見下） |
| 路線規劃 | 地圖點目的地，OTP 算路線畫在地圖上；也能顯示公共自行車站與可借車數 |
| 後台 `/admin` | 不重啟就能切換站牌與方向 |
| 方向過濾 | 自動隱藏「終點站到站」的方向；循環路線不過濾 |
| 公車資料 | 只用 TDX；共用限速器、3 秒等待上限、靜態站序索引（見 [TDX](tdx-tiers.md)） |
| 正式部署 | systemd + Nginx，失敗自動回切，可指定版本 rollback（見 [部署](deployment/production.md)） |
| 觀測 | OpenTelemetry → SigNoz（見 [觀測](observability.md)） |

### 聽錯救援的成果

60 題測試集（六類、含對照組），完全答對從 41.7% 提高到約 90%；幻覺否認、退化迴圈、誤救都降到 0。

關鍵是**真實狀態由工具給，4B 小模型只負責改寫成確認句**。只改 prompt 試過兩次，都沒用。

還沒解決的：模型在呼叫工具前自己改字，或改寫時把聽錯的字唸回去（各約 1–2/60）。要再進步得換更大的模型，或在 ASR 端加熱詞（沒做）。

### 延遲的真正原因

「我要去虎尾」這題曾經要 119 秒才查完，處理後降到 0.07 秒，429 錯誤歸零。根因不是程式慢，而是 TDX 免費方案的限流：原本逐條查 31 條路線，被限流後還照 TDX 要求等 20～40 秒才重試。
