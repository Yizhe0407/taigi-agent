# 一句話怎麼變成答案

先看一個例子。使用者對 Kiosk 說：「**201 幾分鐘到？**」

![語音對話流程：音訊輸入 → VAD → ASR → AgentSession → 公車工具與 LLM → 台語轉寫 → TTS → 輸出](images/voice-flow.png)

| 步驟 | 誰做 | 手上的資料 |
|---|---|---|
| 1. 判斷說完了 | Silero VAD（偵測有沒有人在說話） | 一段音訊。說話途中插話，也能讓小芸停下來 |
| 2. 聽成文字 | Breeze-ASR-26（語音辨識，ASR） | `201 幾分鐘到` |
| 3. 先過規則 | `IntentRouter`（正規表示式） | 只說路線號、問跨縣市或轉乘、問時刻表，這三種直接回固定說法。這句都不是，交給 LLM |
| 4. 選工具 | Qwen3.5-4B（語言模型，LLM） | 呼叫 `get_arrivals_here(route="201")` |
| 5. 查資料 | 工具 → 交通部 TDX | `往高鐵雲林站：約七分鐘後到這站` |
| 6. 說成一句話 | Qwen3.5-4B | 「201 往高鐵雲林站，大約七分鐘後到。」 |
| 7. 變台語 | HanloFlow + Taibun | 國語句子 → 台語漢字與拼音 |
| 8. 發聲 | Piper（語音合成，用台語資料自己微調） | 台語語音，Live2D 小芸跟著對嘴 |

## 數字不讓模型說

第 5 步的時間是程式算的，第 6 步的模型只負責改寫。這不只是在 prompt 裡拜託，流程本身就這樣設計：

- **每一輪第一次呼叫 LLM，要求它一定要選工具**，不能直接回答。
- 閒聊、道謝、抱怨、聽不清楚也要走工具（`respond_directly`）。模型只標出是哪一種，**句子由系統從預先寫好的說法裡挑**。只有使用者要它「再講一次」時，才由模型自己重述上一句。
- 拿到工具結果之後，模型才用一般文字回答。一輪最多 8 回合工具呼叫，超過就回「查詢逾時，請換個方式再問一次」。

只靠模型的話，它會編出一個聽起來合理的時間。這樣做，數字一定有來源。

但這不是百分之百的保證，有兩個缺口：

- 第 6 步的改寫沒有再自動比對數字。prompt 要求模型照抄工具給的時間，但沒有程式檢查，模型仍有可能抄錯。
- 模型呼叫工具的格式一直出錯時，系統會放寬成「可以不選工具」再試一次；模型真的跳過工具直接回答，那段文字會照樣送出。這是為了不讓使用者卡住而留的退路。

**聽錯也走同一套。** 假設 ASR 把「201」聽成本站沒有的「207」：工具發現沒有這條，會自己改查最接近的 201（1 和 7 唸起來像，算很接近），把 201 的真實狀態連同確認句一起交給模型。小芸會說「你是要問 201 嗎？201 大約七分鐘後到。」，不會硬猜，也不會說「沒有這班車」。

## 模型能用的工具

| 工具 | 回答 |
|---|---|
| `get_arrivals_here` | 某條路線還有幾分鐘到本站 |
| `get_stop_arrival_statuses_here` | 本站所有路線現在的狀態 |
| `get_routes_at_stop_here` | 本站有哪些路線 |
| `get_routes_at_stop` | 別的站牌有哪些路線 |
| `get_route_stops` | 某條路線停哪些站 |
| `get_arrivals_to_destination` | 要去某地，本站哪幾條直達、多久到 |
| `check_stop_on_route` | 某條路線有沒有停某站 |
| `respond_directly` | 非公車的情況，由系統挑固定說法 |
| `end_conversation` | 使用者說「多謝」「按呢就好」時道別並結束（只有語音模式） |

到站時間只查 Kiosk 所在的這一站。不做完整時刻表；要轉乘的走地圖路線規劃（見 [route-planning.md](route-planning.md)）。

## 程式在哪

| 資料夾 | 做什麼 |
|---|---|
| `backend/agent/` | 對話迴圈：訊息、呼叫 LLM、派送工具、IntentRouter。不放公車邏輯 |
| `backend/tools/` | 給模型的工具 |
| `backend/services/` | 公車邏輯（離站決策、路線規劃、Kiosk 設定）與 TTS 流程 |
| `backend/providers/` | 外部資料的接口：TDX、ASR、路線規劃引擎 OTP、公共自行車 |
| `backend/voice/` | WebRTC 即時語音，可以打斷 |
| `backend/pipeline/` | 國語轉台語的文字處理 |
| `frontend/` | Vue 畫面：離站首頁、小芸、地圖、`/admin` 後台 |

要做的事對應到：

- **加一種查詢** → 照 CLAUDE.md「新增工具流程」：provider → service → `tools/` → 登記到 `agent/tools.py`
- **換站牌** → 開 `/admin`，不用改程式
- **換公車資料源** → 在 `providers/` 加一個新實作，再到 `services/departures/provider.py` 換掉接線；上層不用動
- **改某個模組** → 先讀 [逐模組細節](architecture-reference.md)

## 限制

- TDX 被限流或連不上時，改用最近一次查到的資料，最舊約 6 分鐘前。快取記的是「幾點幾分到」，所以分鐘數會照現在時間倒數；但這段期間公車若誤點，系統看不到。再舊就只能回「查詢失敗」。各層快取見 [架構參考](architecture-reference.md#快取)。
- TDX 只告訴我們「還沒發車」，不給預計發車時刻，所以畫面寫「未發車」但沒有時間。
- 對話紀錄存在單機 SQLite，API 限流與 TDX 限速器也只在單一程序內，要多台機器部署得另外處理。
