# 為什麼不做「台語版 Google Maps」

Google Maps 回答「我要從 A 到 B 怎麼走」。
站在站牌前的人問的是另一件事：**我已經在這了，現在還有什麼車可以搭？**

這個系統只回答第二個問題。

## 它給的答案

每條路線、每個方向，都會落在下面其中一種狀態，畫面用大字顯示，小芸用台語唸出來。文件裡的狀態名稱都照這張表。

| 狀態 | 什麼時候 |
|---|---|
| 即將到站 | 不到 4 分鐘 |
| 可以等 | 4～20 分鐘 |
| 等待較久 | 21 分鐘以上 |
| 尚未發車 | 這班還沒從起點出發（TDX 不給預計發車時刻，所以沒有時間） |
| 末班已過 | 今天沒車了 |
| 今日未營運 | 這條路線今天不跑 |
| 資料異常 | 查不到能用的資料 |

分鐘數是 TDX 給的預估秒數無條件捨去；門檻寫在 `backend/services/departures/classification.py`。首頁大卡用上表的名稱；右邊的路線列表空間小，會改用短字：未發車、末班駛離、狀態不明。

台語語音是輔助，不是唯一入口。它幫忙唸重點、減少閱讀，也聽得懂短指令：「還有車無」、「二〇一路」、「往斗六」。

## 為什麼這樣取捨

這一段是設計時的判斷，**沒有做過使用者測試驗證**。

我們假設：長輩多半知道要搭哪一條，看過時刻表、坐過很多次，真正不確定的是「這班還來嗎」「末班開走了沒」「現在幾分到」。這些都不需要地圖。

反過來，地圖選點要縮放、拖圖釘、看懂路線圖，對不常用手機的長輩負擔重。會用地圖規劃路線的，多半是學生、觀光客、陪同的子女。

| 做 | 不做（或降成次要） |
|---|---|
| 固定站牌的離站首頁 | 用說的講目的地，再幫你規劃轉乘路線 |
| 大字、高對比、少操作 | 任意地址轉座標 |
| 台語播報本站重點 | 多段轉乘與完整步行導航 |
| 短語音指令（路線、方向、站名） | QR 分享 |

問小芸「我要去虎尾」，她會回答本站有哪幾條直達、多久到。需要轉乘的，才交給地圖路線規劃，那是給會用地圖的人的次要功能（見 [路線規劃](route-planning.md)）。

## 語音只求聽懂短指令

台語、華語、地名、路線號常常混著講，完整轉寫和地名判斷都不穩。所以 ASR 只求聽懂**短指令**：路線號、方向、站名。

聽錯時，系統會挑最接近的那個先查，回答時用「你是要問 201 嗎？」確認，不會硬猜，也不會直接說「沒有這班車」。

TTS 的價值不是「會唸」，而是讓人聽完就知道該不該等。

## 放在不同站牌

同一套系統，放在不同站牌服務的人不一樣。目前每一站的畫面都相同，以離站首頁為主；下表是設計時預想的差異，還沒有依站牌切換畫面：

| 站牌 | 主要使用者 | 最常問的 |
|---|---|---|
| 鄉鎮小站（口湖、四湖、台西…） | 在地長輩 | 還有車嗎、末班開了沒 |
| 雲科大、虎尾科大 | 學生、接送家長 | 到站時間，偶爾查校外路線 |
| 虎尾火車站、高鐵雲林站 | 觀光客 | 去景點怎麼走 |

Kiosk 在哪一站、哪個方向，由 `/admin` 後台設定，不用重啟。
