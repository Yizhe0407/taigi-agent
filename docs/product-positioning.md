# 產品定位

系統處理的問題是：使用者已經在站牌前，現在有哪些車可以搭、要等多久。從 A 地到 B 地的完整路線規劃不是主要功能。

## 狀態定義

每條路線的每個方向會歸入下列其中一種狀態，畫面以大字顯示，小芸以台語播報。文件中的狀態名稱都依照這張表。

| 狀態 | 條件 |
|---|---|
| 即將到站 | 不到 4 分鐘 |
| 可以等 | 4～20 分鐘 |
| 等待較久 | 21 分鐘以上 |
| 尚未發車 | 這班還沒從起點出發（TDX 不提供預計發車時刻，所以不顯示時間） |
| 末班已過 | 今天已沒有班次 |
| 今日未營運 | 這條路線今天不行駛 |
| 資料異常 | 沒有可用的資料 |

分鐘數由 TDX 的預估秒數無條件捨去而來，門檻定義在 `backend/services/departures/classification.py`。首頁大卡使用上表名稱；右側路線列表空間較小，使用較短的名稱：未發車、末班駛離、狀態不明。

台語語音是輔助入口，用來播報重點、讓使用者少看字，並接受短指令，例如「還有車無」「二〇一路」「往斗六」。

## 取捨

以下是設計時的假設，沒有經過使用者測試：

- 長輩多半已知道要搭哪一條路線，不確定的是這班還會不會來、末班是否已過、還要等幾分鐘，這些問題用不到地圖。
- 地圖操作（縮放、拖曳圖釘、看路線圖）對不常用手機的長輩負擔較重。會用地圖規劃路線的，多半是學生、觀光客或陪同的家人。

因此：

| 主要功能 | 次要或不做 |
|---|---|
| 固定站牌的離站首頁 | 以語音說出目的地後規劃轉乘路線 |
| 大字、高對比、少操作 | 任意地址轉座標 |
| 台語播報本站狀態 | 多段轉乘與完整步行導航 |
| 短語音指令（路線、方向、站名） | QR 分享 |

問小芸「我要去虎尾」，她會回答本站有哪幾條直達路線與到站時間。需要轉乘時，使用地圖路線規劃（見 [路線規劃](route-planning.md)）。

## 語音範圍

台語、華語、地名與路線號經常混用，完整轉寫與地名判斷都不穩定。所以 ASR 只處理短指令：路線號、方向、站名。

辨識錯誤時，系統改查讀音最接近的路線或站名，並以「你是要問 201 嗎？」的形式確認，不直接回答「沒有這班車」。

## 不同站牌的使用者

目前所有站牌使用相同畫面，以離站首頁為主。下表是設計時預期的差異，尚未依站牌調整畫面：

| 站牌 | 主要使用者 | 常見問題 |
|---|---|---|
| 鄉鎮小站（口湖、四湖、台西等） | 在地長輩 | 還有沒有車、末班過了沒 |
| 雲科大、虎尾科大 | 學生、接送家長 | 到站時間，偶爾查校外路線 |
| 虎尾火車站、高鐵雲林站 | 觀光客 | 前往景點的路線 |

Kiosk 所在的站牌與方向在 `/admin` 後台設定，不需重啟。
