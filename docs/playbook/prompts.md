# 派工 prompt 範本

複製填空。每份都含三要素：目標與動機、驗收條件、回報格式。用哪個模型見 `model-dispatch.md`。`{...}` 是填空處。

**每個 prompt 結尾都附：**

```
回報規則：只回結論 + 檔案:行號，不貼大段內容；超過 30 行的產物寫到檔案回傳路徑；
做不到就說「做不到，因為 {原因}」，不要編造；回報上限 {N} 行。
```

## 1. 搜尋（Explore，haiku；範圍模糊或跨多目錄用 sonnet）

```
在 {目錄/整個 repo} 找 {目標}。動機：{為什麼找}。搜尋廣度：{medium / very thorough}。
驗收：每個結果附 檔案:行號；明說「找完了」或「還有 {範圍} 沒掃」；找不到也要回報並列出試過的關鍵字。
回報：bullet，每條一行，≤20 行。
```

## 2. 實作（general-purpose，sonnet）

```
目標：{一句話}。動機：{為什麼}。
先讀：CLAUDE.md、{相關檔案}。照 CLAUDE.md「新增工具流程」分層放檔案。
限制：{不可動的檔案/介面}；tool handler 回傳 str；不新增依賴（要的話先停下回報）。
驗收：uv run pytest 綠、uv run ruff check . 乾淨（frontend 用 pnpm typecheck）；
{具體輸入 → 預期輸出}；新邏輯至少一個測試。
回報：1) 改了哪些檔（檔案:行號） 2) 做了什麼、為什麼、可能的坑 3) 測試輸出最後 5 行。
```

## 3. 重構（sonnet；跨模組邊界先派 Plan）

```
目標：把 {現狀} 重構為 {目標}。動機：{痛點}。
限制：對外行為不可變。先跑 pytest 記基準，重構後必須同樣全綠。只動 {檔案清單}，需要動範圍外的就停下回報。
驗收：pytest 前後皆綠、無新增 skip；ruff 乾淨；diff 不含行為變更（無新分支、無改測試預期值）。
回報：1) 動了哪些檔 2) 結構前後對照（各 ≤3 行） 3) 沒動但建議之後動的。
```

## 4. 研究（general-purpose 或 claude-code-guide，sonnet；要 WebSearch）

```
問題：{具體問題}。動機：{這個答案決定什麼}。
優先序：官方文件 > 官方 repo/changelog > 其他。禁止憑記憶回答版本號、參數名、價格。
驗收：每個事實附 URL；查不到標 NOT FOUND，不推測；有版本差異註明版本與查證日期。
回報：逐條回答，每條 = 答案一句 + URL，≤30 行。
```

## 5. 審查（sonnet；高風險 diff 用 opus）

```
審查：{diff / 檔案 / PR}。動機：{要防什麼}。你是 fresh context，不要假設寫的人是對的，先讀 CLAUDE.md 相關 gotchas。
必查：TDX direction 是 0/1 不是 1/2；messages 截斷以 tool-call 輪次為單位；tool handler 回傳 str；
測試有斷言行為（不是只斷言 mock 被呼叫）；{本次特別要查的點}。
驗收：每個 finding = 位置（檔案:行號）+ 問題一句 + 修法一句；沒問題就說「查過 {清單}，無 finding」。
回報：嚴重的排前面，≤25 行。
```

## 6. 驗證 / read-back（haiku）

```
你是 fresh context 驗證者，之前的對話你都沒看過（刻意的）。讀 {檔案路徑}，回答：
1. 這份文件/程式要你做什麼？（3 句內）
2. 有沒有指令矛盾、路徑不存在、或看不懂怎麼執行的地方？逐條列。
3. {針對性問題，例：照這份文件，新增一個 provider 要動哪些檔？}
答「無」之前，必須先實際確認每個提到的路徑存在。回報：逐題答，≤20 行。
```
