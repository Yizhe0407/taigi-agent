# TDX 方案與限流

公車資料全部來自交通部 TDX。TDX 以點數計費，公車 API 大約每 1,500 次呼叫扣 1 點。

| 方案 | 頻率上限 | 每月點數 | 是否夠用 |
|---|---|---|---|
| 基礎會員（免費） | 5 次/分 | 3 點 | 不夠，約兩天用完，之後當月無法查詢 |
| 銅級（200 元/月，學生半價） | 5 次/秒 | 200 點 | 夠，本系統每月約用 76 點 |

正式使用需要銅級。升級後在 `backend/.env` 設定：

```dotenv
TDX_RATE_LIMIT=5/s     # 基礎會員用 5/min
```

## 減少呼叫與等待

- 所有 TDX 請求共用一個限速器排隊，一般情況不會收到 429。收到 429 時，整把金鑰暫停到 TDX 指定的時間。
- 使用者提問時最多等上游 3 秒，逾時就用快取的舊資料；沒有舊資料才回「暫時查不到」。
- 查詢目的地時，先用靜態站序篩出會經過目的地的路線（以虎尾為例，31 條路線篩到約 5 條），只查這些路線的即時資料。

使用舊資料時，分鐘數會依目前時間倒數，但這段期間的誤點不會反映出來（見 [架構](architecture.md#限制)）。
